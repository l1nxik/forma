# Архитектура Forma 0.2

```text
React / TypeScript
    → именованные операции Tauri IPC
Rust desktop host
    → авторизованный REST на 127.0.0.1 и случайном порту
Java / Spring Boot
    → сервисы и транзакции JDBC
SQLite в пользовательской папке приложения
```

## Границы модулей

`src/pages` компонует Today, Tasks, Projects и Focus. Редакторы и повторно используемые элементы находятся в `src/components`. `SegmentedControl` отвечает за общее поведение вкладок, а `ProjectNavigation` — за дерево боковой панели. Запуск приложения и клавиатурные команды выделены из композиции рабочего пространства.

`src/state` содержит чистые функции дат, выбора и иерархии проектов, отображение времени и загрузку данных. `useWorkspace` владеет снимком, состоянием загрузки, блокировкой записей и обработкой конфликтов. Счётчик поколения отбрасывает устаревшие ответы после смены даты или размонтирования. История навигации хранит раздел, проект и день в памяти окна. Новый переход после возврата отбрасывает прежнюю ветку вперёд; повторное открытие того же места не дублирует запись. Настройка узкой панели использует прежний ключ sidebarCollapsed, поэтому обновление не требует миграции базы.

`src/design` разделён на layout, navigation, controls, planner, tasks, projects, focus, dialogs, calendar и responsive. Токены и палитры централизованы. SVG-логотип рисуется вектором, без шрифта, растровой модели или сетевого ресурса. VS Code palettes извлекаются только скриптом разработки; приложение ничего не скачивает.

Java `api` преобразует HTTP в вызовы сервисов. Настройки обслуживает `PreferencesService`, а не другой контроллер. `service` проверяет бизнес-правила и задаёт транзакции, `persistence` содержит SQL, `domain` — DTO и ограничения. `Clock` внедрён в сервисы задач, проектов и Focus, чтобы временные сценарии проверялись без ожидания реального времени.

Rust управляет Java, меню, single-instance, HTTP-клиентом и необязательным нативным материалом боковой панели. Webview не получает токен и не обращается к Java напрямую.

## Процессы и API

Небольшой C-launcher вызывает `execv` для конкретного `Resources/backend/runtime/bin/java`. Установленная Java, shell и PATH не используются. Rust передаёт пути и свежий токен из двух UUIDv4 через окружение. Java выбирает свободный порт и сообщает `FORMA_READY` после инициализации и миграций.

При завершении host закрывает stdin. Java наблюдает EOF и останавливается; это работает и при аварийном завершении родительского процесса. Host ждёт до двух секунд и завершает процесс принудительно только при необходимости. Single-instance поднимает существующее окно.

REST слушает только IPv4 loopback. Фильтр требует секретный заголовок, сравнивает его constant time, проверяет Host и адрес клиента, отклоняет browser Origin. Rust допускает только известные операции и личное workspace, проверяет UUID, формы дат и размер запроса. Один повторно используемый HTTP-клиент имеет timeout и отключённый системный proxy. CSP ограничивает webview ресурсами приложения и IPC.

Эта граница предотвращает обращения сторонних сайтов и случайных локальных клиентов. Она не защищает от программы с полномочиями текущего пользователя. SQLite не зашифрована.

## Хранение и миграции

SQLite использует WAL, foreign keys, busy timeout, synchronous FULL и одно соединение Hikari. Запись задачи с историей статуса, изменение плана, переход Focus и исправление сессии выполняются транзакционно. Редактирование проверяет `revision`; устаревшая версия возвращает 409.

- V001: задачи, история статусов и настройки.
- V002: проекты, привязка задач, дневные планы, сессии и рабочие отрезки. Старые `scheduled_date` превращаются в явные планы; поля и история сохраняются.
- V003: родитель проекта и индекс иерархии.

Каждый исходный SQL проверяется по SHA-256 и никогда не изменяется после применения. Более новая версия схемы или несовпадение checksum блокируют запуск. Перед обновлением создаётся `VACUUM INTO` снимок, который затем атомарно переименовывается. После запуска проверяются целостность и foreign keys.

Данные пользователя и резервные копии хранятся вне `.app`. Скрипты очистки работают только со сгенерированными пакетами приложения.

## Задачи, планы и проекты

Дедлайн — календарная дата без часового пояса. Время создания и завершения — UTC Instant. Frontend строит локальные дни из компонентов Date, не из `toISOString()`. Today отслеживает смену дня, а выполненные за день выбираются по фактическому `completedAt`.

План хранит дату, версию и упорядоченные ID. Автоплан исключает завершённые задачи и архивные ветки; сначала учитывает наступивший дедлайн, затем приоритет, дату и стабильный порядок. Предложение не пишет в базу до сохранения.

У проекта один родитель. Сервис запрещает циклы, чужое workspace и новые назначения в архивную ветку. Родительский экран собирает задачи и время потомков без копирования записей. Удаление задачи сохраняет измеренное время Focus и снимок её названия.

## Focus и статистика

На workspace допускается одна незавершённая сессия. Работа и перерыв — разные типы. Начало и продолжение открывают отрезок; пауза и завершение закрывают его. Сумма отрезков является источником истины, JS interval только обновляет экран. Закрытие окна не ставит работающий таймер на паузу.

Перерыв имеет целевую длительность. При чтении и изменении состояния сервис сверяет сохранённые timestamps и завершает его точно на целевом времени, в том числе после сна или перезапуска. Фоновый scheduler для этого не нужен.

Статистика учитывает только рабочие отрезки и обрезает их по границам локальных дней в переданном IANA timezone. Паузы и перерывы исключены. Переход через полночь и дни DST длиной 23 / 25 часов не считаются фиксированными интервалами по 24 часа. Исправление завершённой сессии заменяет её отрезки одним новым интервалом после проверки версии и диапазона.

## Материал и доступность

По умолчанию боковая панель непрозрачная. При увеличении прозрачности на macOS 26+ под ней создаётся `NSGlassEffectView`. React отправляет только изменившуюся геометрию через ResizeObserver; постоянного цикла кадров нет. Все AppKit-вызовы выполняются на main thread. При 0%, reduced transparency и high contrast нативный материал убирается. На старых системах остаётся CSS-подложка.

Темы задают светлую / тёмную нативную appearance. Reduced motion отключает движение. Переключатели имеют radio-семантику и поддержку стрелок; календарь активности использует один Tab-stop вместо 365 последовательных остановок.

## Сборка

Кэши находятся в `.noindex`. Упаковщик сначала проверяет подписанный временный пакет, затем обновляет каноническое приложение. После успешной упаковки промежуточные `.app` снимаются с регистрации LaunchServices и удаляются. Исходный ZIP не включает runtime, зависимости, базы и кэши.

Проверки и оставшиеся ограничения перечислены в [verification.md](verification.md).

## Платформенная упаковка

`npm run package:desktop` выбирает macOS arm64 или Windows x64. На Windows используется обычная системная рамка окна, непрозрачная панель и обозначения Ctrl; нативный стеклянный материал остаётся возможностью macOS. Windows launcher передаёт Java только стандартные потоки, запускает её с Unicode-путями без shell и помещает в Job Object. Это связывает время жизни Java с процессом launcher при принудительной остановке.

Пакеты создаются в `release.noindex/`, не поверх установленной Forma. Экспорт исходников использует список файлов Git и его ignore-правила. GitHub Actions собирает пакеты на отдельных native runners, не имеет права записи в репозиторий и не публикует релизы. Windows-путь подготовки пока требует проверки на Windows.
